# 四層理解力思考框架

## 什麼時候用

套用這個框架當：

- 使用者說「我聽不懂/看不懂/學不會」
- 面對一個複雜陌生的問題，不知從何下手
- 需要深入理解一個概念、系統或程式碼庫
- 幫使用者拆解資訊、組織知識、或診斷問題根源
- 任何需要系統性思考的場景

## 核心理念

> 理解能力差不是智商問題，而是缺少四種主動加工資訊的思考力。
> 「你不是聽不懂，你是不會思考著聽；你不是學不會，你是不會思考著學。」

## 四層思考框架

### 第一層：切割式思考（Segmentation）

**把大塊資訊切成有邊界的顆粒。**

資訊的顆粒越小，越容易記憶和連接。

**使用時機：** 面對長文、演講、會議、複雜任務

**實作步驟：**
1. 聽取/閱讀時，在心裡快速打標籤分類
2. 用邏輯樹拆出：核心觀點 → 支撐論據 → 行動步驟
3. 接任務時先問三個問題：
   - **目標是什麼？**（What）
   - **條件是什麼？**（Context/Constraints）
   - **關鍵動作有哪些？**（How）
4. 讀文章時用符號標出：論點、論據、因果關係、疑問點

> 切割越細 → 邏輯越輕 → 理解越透 → 後續做事越不會跑偏

### 第二層：關聯式思考（Association）

**給新資訊找掛鉤，掛在既有的知識網上。**

人的記憶像一面大網，新資訊要融進去必須找到原有的網線。

**使用時機：** 學習新概念、第一次接觸陌生領域

**實作步驟：**
1. 看到新概念時問自己：「這像我已知的哪個事物？」
2. 能不能用一個生活例子來解釋？
3. 找出概念之間的相似性 vs 差異性
4. 用類比（Analogy）把陌生變熟悉

> 連得越多 → 知識的網越密 → 新東西積得越牢固

### 第三層：升維式思考（Elevation）

**暫時離開細節，跳到更高的視角看全局。**

很多理解障礙是因為被細節拖住，看不到全貌。

**使用時機：** 被困在細節中、問題反覆出現、需要策略性思考

**實作步驟：**
1. 停止追問「怎麼做」，開始追問「為什麼」
2. 一層層往上：葉子 → 樹枝 → 樹幹 → 整片森林
3. 把問題放到不同維度：
   - **環境維度**：這個問題發生在什麼背景下？
   - **時間維度**：短期 vs 長期會怎麼演變？
   - **全局維度**：誰還受影響？上下游是什麼？
4. 從系統結構層面找真正的病根

> 習慣升維 → 看問題自然有上帝視角

### 第四層：閉環式思考（Closed-Loop）

**從知道推進到行動，透過回饋修正形成循環。**

理解的最終價值不在於聽懂了，而在於能落地。

**黃金公式：** 知道 → 實踐 → 覆盤 → 再優化

**使用時機：** 學了新東西之後、做完一件事之後、知識感覺「懂了但用不上」

**實作步驟：**
1. **知道** → 整理知識點，確認自己理解
2. **實踐** → 今天就試著用一次，記錄過程與效率
3. **覆盤** → 明天檢討哪些環節卡住、拖慢進度
4. **再優化** → 調整策略再來一輪

**過濾機制：** 反覆嘗試仍不起作用的知識 → 暫放，不是當前核心技能
**最終目標：** 把每一點知識變成行動力，讓理解力變成可量化的輸出力

## 套用流程（給 Agent 使用）

當使用者需要深入理解某件事時：

```
Step 1: 切割 → 先幫他把資訊拆成小塊（重點清單/分段摘要）
Step 2: 關聯 → 連結他已知的經驗或知識（舉例+類比）
Step 3: 升維 → 拉到更高視角看全局脈絡（Why+全景圖）
Step 4: 閉環 → 總結出行動點（下一步做什麼）
```

## 實戰範例

### 範例：理解一個開源專案

- **切割：** 拆出架構圖、核心模組、檔案結構、API 接口
- **關聯：** 「這個 pattern 像 React 的 context + Redux 的 store」
- **升維：** 「這個專案解決的是前端狀態管理的根本矛盾」
- **閉環：** 今天跑一個 demo，明天試著改一個 feature

### 範例：幫使用者分析問題

- **切割：** 「你遇到的問題可以拆成 A、B、C 三個子問題…」
- **關聯：** 「這跟上次你遇到的 XXX 問題其實是同一個 pattern」
- **升維：** 「從產品層面來看，這個 bug 的根源是設計假設錯誤」
- **閉環：** 「先試試解法 1，明天回報結果，不行再換解法 2」
