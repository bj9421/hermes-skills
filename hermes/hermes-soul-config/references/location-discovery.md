# SOUL.md Location Discovery (Corrected — 2026-07-16)

## Problem

User asked "怎麼還有一個 SOUL.md 是自動產生的嗎" after finding two SOUL.md files on their Docker container:

```
/home/hermes_data/SOUL.md           → 376 chars, default English identity (513 bytes disk)
/home/hermes_data/.hermes/SOUL.md   → 1955 chars, Chinese custom identity (Hermes_Pi)
```

Host mapping: `/opt/data/` (host) → `/home/hermes_data/` (container via Docker volume)

## How Hermes Finds SOUL.md

`prompt_builder.py:load_soul_md()` reads from:

```python
soul_path = get_hermes_home() / "SOUL.md"
```

`get_hermes_home()` resolves (in order):
1. Context-local override (`_HERMES_HOME_OVERRIDE`)
2. `$HERMES_HOME` env var
3. Fallback: `Path.home() / ".hermes"`

**Key insight:** the `.hermes/` subdirectory is already in `get_hermes_home()` — never append it again.

## Two Key Realities Discovered

| File | Read by Hermes? | Content | Auto-regenerated? |
|------|:--------------:|---------|:-----------------:|
| `$HERMES_HOME/SOUL.md` | ✅ **Yes — identity slot #1** | Chinese (after fix) | ❌ (custom content safe) |
| `./SOUL.md` (CWD match) | ✅ Yes | English default | ✅ by `_ensure_default_soul_md()` |
| `.hermes/SOUL.md` | ❌ No | Chinese (stale copy) | ❌ (not in search path) |

## Root Cause of the "Regeneration" Mystery

1. **Two SOUL.md files, different paths:** The root one was auto-generated by `_ensure_default_soul_md()` (called at every startup via `ensure_hermes_home()`); `.hermes/SOUL.md` was the user's custom one that Hermes never read
2. **Not a ghost:** Just init code doing its job — when the root SOUL.md was missing, `_ensure_default_soul_md()` wrote the 513-byte default English identity
3. **Docker `ls` invisibility:** The container shell couldn't list `/home/hermes_data/` (Docker volume mount quirk on this RPi4), making the file seem "non-existent" to `ls` but fully readable by `read_file` — creating the false impression of a phantom file

## Corrected Lesson for Future Investigations

When a file keeps reappearing and the user asks why:

1. **Read the actual code** that writes it — `_ensure_default_soul_md()` in `config.py` — don't speculate about ghosts or auto-generation from unrelated processes
2. **Cross-check tools** — if `terminal ls` says NO but `read_file` says YES, trust `read_file` (Docker quirk)
3. **Verify `$HERMES_HOME` resolution** on the actual container — `python3 -c "from hermes_constants import get_hermes_home; print(get_hermes_home() / 'SOUL.md')"`
4. **Don't jump to conclusions from incomplete data** — the first analysis said ".hermes/SOUL.md is dead" without verifying the active path on this specific Docker setup

## Resolution

1. Chinese identity written to `$HERMES_HOME/SOUL.md` (correct path)
2. `_ensure_default_soul_md()` leaves custom content alone (checks for legacy template first)
3. Stale `.hermes/SOUL.md` renamed to `.nouse` as recovery backup
